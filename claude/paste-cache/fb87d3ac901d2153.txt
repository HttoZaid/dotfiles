Three bugs, in order of impact:

**1. The static key used for the third ECDH is wrong — this is the main rejection cause**

whatsmeow does:
```go
encryptedPubkey := nh.Encrypt(cli.Store.NoiseKey.Pub[:])
err = nh.MixSharedSecretIntoKey(*cli.Store.NoiseKey.Priv, serverEphemeralArr)
```

It sends `cli.Store.NoiseKey` (a *dedicated Noise static key*), not the Signal identity key. Your code uses the identity key as the Noise static key:

```cpp
// Your code
auto ident_opt = m_store->get_identity_key_pair();
static_key_pair.pub_key = ident_opt.value().pub_key;
static_key_pair.priv_key = ident_opt.value().priv_key;
```

This is the conceptual mistake. The Signal identity key and the Noise static key are **two separate key pairs** in WhatsApp's multi-device protocol. The Noise static key is what goes into the `ClientFinish.static` field and drives the third ECDH. The Signal identity key (`eident`) goes into `devicePairingData.eident` in the client payload. You're using the same key for both, which means:

- The third `mix_into_key` produces a different chaining key than the server expects
- The `encrypt(client_payload)` therefore uses a wrong message key
- Server decrypts garbage → rejects

Fix: generate (and persist) a **separate** Noise static key pair (`noise_key` in the store), distinct from the identity key. Use `noise_key` in the `ClientFinish.static` + third ECDH. Use the Signal identity key only in `eident`.

```cpp
// In connect():
auto noise_key = Crypto::generate_key_pair();
config_.store->set_noise_key(noise_key);

// In handshake start():
auto noise_key_opt = m_store->get_noise_key();
// ...
auto static_key = m_noise_state.encrypt(noise_key_pub_vec);
auto third_shared = Crypto::ecdh(server_ephemeral, noise_key_priv_vec);
m_noise_state.mix_into_key(third_shared);
// ... then encrypt client payload
```

**2. Server cert verification is missing entirely**

whatsmeow calls `verifyServerCert(certDecrypted, staticDecrypted)` which validates a two-level cert chain (intermediate signed by `WACertPubKey` using Ed25519, leaf signed by intermediate) and checks the leaf key matches `staticDecrypted`. You're decrypting the payload and doing nothing with it:

```cpp
std::vector<uint8_t> decrypted_payload = m_noise_state.decrypt(encrypted_payload);
// <-- nothing happens here
```

WhatsApp's server almost certainly checks whether the client proceeds as if it validated the cert. If it detects the client is accepting any static key without verification, it can (and does) reject. Even if it doesn't actively check this, skipping it means you're silently accepting a MitM.

You need to unmarshal the `decrypted_payload` as a `CertChain` proto, verify the Ed25519 signature chain using `WACertPubKey` (that byte array from whatsmeow), and confirm the leaf key equals `server_static_key`. If that check fails, abort.

---

**3. The prologue is being prepended to the first frame, but the Noise `start()` only hashes the pattern name — not the prologue as WA expects it**

whatsmeow's `nh.Start(socket.NoiseStartPattern, fs.Header)` passes the WS frame header *as the prologue* to the Noise state. The prologue is mixed into `h` before the handshake starts. Your code does:

```cpp
m_noise_state.start(m_noise_xx, m_prologue);
```

But then in `frame_and_send` you physically prepend `m_prologue` to the first wire frame:

```cpp
wire_frame.insert(wire_frame.begin(), m_prologue.begin(), m_prologue.end());
```

The Noise authenticate of the prologue is correct — it should be mixed into `h`. But check whether your `m_prologue` is exactly the 4-byte WA header (`WA`, version byte, `0x05` or whatever the current value is). The exact bytes matter because it's what the server also hashes on its side. If they differ by even one byte, the `h` values diverge at step 0 and every single encrypt/decrypt after that fails with a GCM auth tag mismatch — meaning the rejection would happen at the `server_static` decrypt step, which you'd see as an exception rather than a server response.

Confirm your `m_prologue` matches `fs.Header` from whatsmeow's `framesocket.go`. It should be the raw 4 bytes prepended to the websocket upgrade: typically `{'W', 'A', 0x06, 0x05}` (or whatever the current version is — check `framesocket.go` in the repo for `Header`).
